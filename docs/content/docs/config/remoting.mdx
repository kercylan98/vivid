跨节点 Actor 通信需在创建 **ActorSystem** 时启用 **Remoting** 并配置消息**编解码**（消息注册或外部 Codec）。配置完成后，**本地与远程的消息投递对业务透明**：**同一套 API**（Tell、Ask、Reply、PipeTo 等）不因目标在本机或远程而改变，无需改写调用方式或增加分支；框架根据 **ActorRef** 的地址自动选择本地投递或跨网络发送，并完成序列化与反序列化。本文说明如何启用 Remoting、配置 消息注册或外部 Codec，以及远程连接读失败时的处理。入口配置见 [Actor System 配置](/docs/config/actor-system-config)。

<Callout type="info" title="位置透明">
配置好 Remoting 与 Codec 后，业务侧**无需区分**目标 Actor 在本机还是远程：`ctx.Tell(ref, msg)`、`ctx.Ask(ref, msg)` 等调用方式完全一致，框架根据 `ref` 的地址自动完成本地投递或跨网络序列化与发送。这就是 **location transparency**（位置透明）。
</Callout>

## 启用 Remoting

通过 **WithActorSystemRemoting(bindAddr, advertiseAddr?)** 启用：

- **bindAddr**（必填）：本机监听地址，如 `"0.0.0.0:8080"`。框架在此地址上启动 Listener 接受连接。
- **advertiseAddr**（可选）：其他节点可访问的地址，例如 `"node1.example.com:8080"`。不传则使用 bindAddr；监听所有网卡或使用端口映射时，应显式设置可访问的地址与端口。

Remoting 使用 TCP 通信。启用后，`Start()` 成功返回表示本地监听已创建；端口占用、监听配置错误会使启动失败，可使用 `errors.Is(err, vivid.ErrorRemotingListen)` 判断，并通过 `errors.As` 获取底层原因。启动失败的实例不可重启，应修正配置后重新创建系统。

监听创建成功不代表远端可达、集群加入成功或业务已就绪；部署探针仍需按服务需求验证。

双方同时发送首条消息时，框架在握手确认前完成连接选择，已建立的健康连接会继续复用。`ves.RemotingInboundConnectionEstablishedEvent` 在入站会话可用后发布；它表示传输连接建立，不能代替集群加入结果或业务就绪确认。

`Tell` 返回、写入 TCP 或连接建立均不表示远端 Actor 已处理消息。连接中断时仍可能丢失消息；重要操作应使用业务应答，并在重试时处理重复请求。`Ask` 超时也不能证明对端没有执行操作。

入站握手请求并行读取并限制并发，单个静默对端不会阻塞后续连接；达到并发上限时暂停接入，释放名额后继续。停止 Remoting 时会取消未完成的拨号并关闭待握手连接；已建立连接的关闭通知只做限时尝试，不保证待发送消息已交付。

## TLS 与双向认证

通过 `WithActorSystemRemotingTLSConfig` 统一配置入站和出站 TLS。下面使用节点证书和受信任 CA 启用 mTLS：

```go
import (
    "crypto/tls"
    "crypto/x509"
    "fmt"
    "os"

    "github.com/kercylan98/vivid"
    "github.com/kercylan98/vivid/pkg/bootstrap"
)

func nodeTLSConfig(certFile, keyFile, caFile string) (*tls.Config, error) {
    certificate, err := tls.LoadX509KeyPair(certFile, keyFile)
    if err != nil {
        return nil, err
    }
    pem, err := os.ReadFile(caFile)
    if err != nil {
        return nil, err
    }
    roots := x509.NewCertPool()
    if !roots.AppendCertsFromPEM(pem) {
        return nil, fmt.Errorf("CA 文件不包含有效证书")
    }
    return &tls.Config{
        Certificates: []tls.Certificate{certificate},
        RootCAs:      roots,
        ClientCAs:    roots,
        ClientAuth:   tls.RequireAndVerifyClientCert,
        MinVersion:   tls.VersionTLS13,
    }, nil
}
```

加载成功后，在创建系统时传入配置，并检查 `Start()` 的返回错误：

```go
config, err := nodeTLSConfig("node.crt", "node.key", "ca.crt")
if err != nil {
    return err
}
system := bootstrap.NewActorSystem(
    vivid.WithActorSystemRemoting("0.0.0.0:8080", "node1.example.com:8080"),
    vivid.WithActorSystemRemotingOption(
        vivid.WithActorSystemRemotingTLSConfig(config),
    ),
)
```

- `Certificates` 提供本节点身份。每个节点同时作为服务端和客户端，mTLS 证书需支持 `ServerAuth` 和 `ClientAuth`，SAN 需包含其他节点访问它时使用的 DNS 名称或 IP。
- `RootCAs` 用于出站服务端证书校验；为空时使用系统根证书。`ServerName` 为空时从每次连接的目标地址推导；显式设置后会用于所有出站目标的名称校验。
- `ClientCAs` 和 `ClientAuth` 控制入站客户端认证。仅需服务端认证时，可省略这两项；启用 mTLS 时，所有节点需信任对方的证书链。

未配置 `TLSConfig` 时使用明文 TCP；启用后不会在 TLS 失败时降级到明文。已建立的连接继续复用，但加密仍有计算和流量开销。启动后不要修改配置及其引用的证书、证书池。

`Start()` 成功只表示本地监听已创建。出站证书或握手失败通过 `ves.RemotingConnectionFailedEvent` 观察，并遵循连接重试策略。mTLS 验证证书身份，不自动绑定对方声明的 Remoting 地址，也不提供业务权限控制或防脑裂能力。

## 消息编解码

框架内部消息由系统自动注册。业务消息可按类型注册，或交给外部 Codec；两种方式可以同时使用，**已注册类型优先，未注册类型才交给外部 Codec**。

### 按类型注册

通过 **WithActorSystemMessageRegister** 配置 **MessageRegister**，可使用 **MessageRegisterFN** 注册编码器与解码器。以固定宽度的订单消息为例：

```go
type Order struct {
    ID    uint64
    Price float32
}

func registerOrder(registry vivid.MessageRegistry) {
    registry.RegisterMessageWithEncoderAndDecoder("Order", new(Order),
        vivid.MessageEncoderFN(func(w *vivid.Writer, message any) error {
            order := message.(*Order)
            w.WriteInteger(order.ID).WriteFloat(order.Price)
            return w.Err()
        }),
        vivid.MessageDecoderFN(func(r *vivid.Reader, message any) error {
            order := message.(*Order)
            if err := r.ReadInteger(&order.ID); err != nil {
                return err
            }
            return r.ReadFloat(&order.Price)
        }),
    )
}
```

创建系统时将注册函数传入，所有通信节点使用相同的注册名称与字段布局：

```go
system := bootstrap.NewActorSystem(
    vivid.WithActorSystemRemoting("127.0.0.1:8080"),
    vivid.WithActorSystemMessageRegister(vivid.MessageRegisterFN(registerOrder)),
)
```

示例使用 `github.com/kercylan98/vivid` 和 `github.com/kercylan98/vivid/pkg/bootstrap`。类型自身实现 **MessageCodec** 时，也可通过 `registry.RegisterMessage` 注册。

### 外部 Codec

通过 **WithActorSystemCodec(codec)** 接入外部编解码器，接口参数使用公开的 Reader/Writer：

```go
type Codec interface {
    Encode(writer *vivid.Writer, message any) error
    Decode(reader *vivid.Reader) (any, error)
}
```

外部 Codec 负责消息体，框架负责消息分帧与注册类型路由。支持多种业务类型时，Codec 需自行区分并恢复对应的 Go 类型。

未注册类型且没有外部 Codec 时，编码返回错误；对方无法识别的注册名称也返回错误，不会转交外部 Codec 猜测。codec 不能为 nil。第三方 Codec 需要匹配当前接口与分帧约定，接入前应验证双向消息往返。

### Reader / Writer

Reader/Writer 用于读写消息字段，也可通过 `vivid.NewWriter()` 和 `vivid.NewReader(data)` 独立使用。

- **WriteInteger / ReadInteger**：Go 1.27 泛型方法，接受固定宽度整数及其自定义类型；例如 `w.WriteInteger(uint32(42))`、`r.ReadInteger(&id)`。泛型入口不接受 int/uint，协议字段应明确宽度。
- **WriteFloat / ReadFloat**：泛型浮点读写，float32 为 4 字节，float64 为 8 字节，支持自定义浮点类型。
- **WriteBool、WriteString、WriteBytes** 与对应的 **Read** 方法：已知字段类型时直接使用。
- **Write(values...) / Read(destinations...)**：方便处理混合字段，复合类型使用反射；Read 目标必须为非 nil 指针。通用路径的 int/uint 固定使用 8 字节。

数值使用大端序，浮点数使用 IEEE 754。字符串、切片、数组与 map 使用 uint32 长度前缀；结构体优先使用自身的 MessageCodec，否则按声明顺序处理导出字段。字段读写不携带字段名或结构体类型，双方必须使用一致的布局，不能替代远程消息注册。nil 指针、nil 接口和循环引用不受支持；nil 与空集合均编码为零长度，不保留两者的区别。

首次错误会保留，后续读写停止；失败前的字段可能已经更新。所有通信节点需使用相同的消息格式。

读取期间不要修改输入缓冲，解码后的字符串和字节切片可独立使用。Reader 会复用目标切片的容量，需要保留旧值时应使用新目标或复制数据。Writer.Bytes 返回当前缓冲的视图，继续写入可能改变已有视图。Reader/Writer 实例不可并发使用。

### 解码资源预算

Reader 默认限制解码资源，避免异常输入引起过深嵌套或大量内存申请：

| 配置 | 默认值 | 统计范围 |
|------|--------|----------|
| `MaxDepth` | 64 | 复合类型和消息解码的嵌套层数 |
| `MaxElements` | `1 << 20` | 切片、数组元素和 map 条目的累计数量，嵌套集合合并统计；字符串与字节切片不计入 |
| `MaxAllocationBytes` | `64 << 20`（64 MiB） | 框架解码过程中累计申请的内存估算值 |

同一个 Reader 的多次读取共享预算；远程通信按单个信封统计，包含地址和消息体。省略配置或将字段设为零时，使用对应默认值。分配预算是估算值，不等同于实际堆内存上限。

通过远程选项调整接收侧预算：

```go
limits := vivid.DecodeLimits{
    MaxDepth:           32,
    MaxElements:        100_000,
    MaxAllocationBytes: 16 << 20,
}
system := bootstrap.NewActorSystem(
    vivid.WithActorSystemRemoting("127.0.0.1:8080"),
    vivid.WithActorSystemRemotingOption(
        vivid.WithActorSystemRemotingDecodeLimits(limits),
    ),
)
```

独立使用时可传入 `vivid.NewReader(data, limits)`。超限通过 `errors.Is(err, vivid.ErrDecodeLimit)` 判断，之后该 Reader 停止读取；远程消息不会投递，连接按下方的读失败流程处理。

自定义 Codec 使用 Reader 字段方法时自动受限。自行分配内存或遍历自定义集合时，应在操作前调用 `reader.ReserveAllocation(bytes)` 或 `reader.ReserveElements(count)` 并检查错误；第三方解码库的资源限制需自行配置。

## 远程连接读失败处理

连接读取、帧解析或消息解码失败时，当前会话会关闭。可订阅 **`ves.RemotingConnectionClosedEvent`**，通过 `Address`、`PeerClosed` 和 `Error` 获取关闭原因；有待发送消息时，系统会尝试重新连接。

## 远程连接重试与死信

向远程节点发送消息时，连接失败后按 **ActorSystemRemotingOptions** 中的策略有限重试。**NewActorSystemRemotingOptions()** 默认提供：额外重试 10 次、初始延迟 500ms、最大延迟 10s、退避因子 2.5，启用随机抖动。可通过 **WithActorSystemRemotingOption** 配置单项或使用 **WithActorSystemRemotingReconnect** 批量配置：

- **ReconnectLimit**：首次拨号失败后的额外重试次数，0 表示不重试。对应 **WithActorSystemRemotingReconnectLimit**。
- **ReconnectInitialDelay** / **ReconnectMaxDelay**：初始与最大退避间隔，首次重试也受最大值约束。对应 **WithActorSystemRemotingReconnectInitialDelay**、**WithActorSystemRemotingReconnectMaxDelay**。
- **ReconnectFactor**：有限且不小于 1 的退避因子，1 表示固定间隔；非法值忽略。对应 **WithActorSystemRemotingReconnectFactor**。
- **ReconnectJitter**：启用后，在当前退避间隔的 50% 到 100% 之间随机选择延迟。对应 **WithActorSystemRemotingReconnectJitter**。

退避期间的新消息进入待发送队列，不会提前触发拨号。重试次数限制针对当前 Endpoint 的连接过程；后续新消息仍可重新发起连接，不是对某个地址永久禁用。

双方同时首次建连时，正常的重复连接仲裁不消耗重试次数，`ReconnectLimit` 为 0 也可完成连接选择。若优选拨号失败，框架会先尝试接管已接入的备用连接；备用连接仍受原握手超时约束，全部失败后才按重试策略处理待发送消息。

连接失败时可订阅 **`ves.RemotingConnectionFailedEvent`**，通过 `Address` 和 `Error` 查看原因。重试耗尽后，待发送消息转为死信，可通过 **`ves.DeathLetterEvent`** 监控，参见 [死信](/docs/basics/death-letter)。

跨节点发送消息的双方都应启用 Remoting。

## 与集群配合

在启用 Remoting 的前提下，将 **WithActorSystemClusterOptions(opts...)** 直接传给 **bootstrap.NewActorSystem** 启用集群，使用 **WithActorSystemClusterSeeds(addresses...)** 配置种子地址。集群使用 Remoting 的地址与编解码进行节点间成员发现与通信。完整示例见 [快速开始](/docs/cluster/quick-start)。

## 与引用解析配合

远程节点的引用常以字符串形式存储或从配置/服务发现获取。使用 **system.ParseRef(actorRef string)** 可将字符串解析为引用（不要求目标存在），再用于发消息。详见 [Actor 引用](/docs/basics/actor-ref)。
