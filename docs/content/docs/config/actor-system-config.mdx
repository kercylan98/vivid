title: Actor System 配置

创建 **ActorSystem** 时通过 **`vivid.ActorSystemOption`** 配置系统级行为，所有选项汇总在 **`vivid.ActorSystemOptions`** 中。远程通讯、指标等专题见下方链接。

## 配置项一览

| 选项 | 说明 |
|------|------|
| **WithActorSystemContext** | 系统根 context；未指定时使用 `context.Background()` |
| **WithActorSystemLogger** | 系统默认 Logger；未指定时使用 `log.GetDefault()` |
| **WithActorSystemDefaultAskTimeout** | 全局默认 Ask 超时；仅 >0 时生效，默认 1 秒 |
| **WithActorSystemStopTimeout** | **Stop()** 的最大等待时间；仅 >0 时生效，默认 1 分钟。**Stop()** 不传参时使用该值 |
| **WithActorSystemSupervisionStrategy** | 系统默认监督策略；nil 时顶层使用“停止”。详见 [监督策略](/docs/config/supervision) |
| **WithActorSystemEnableMetrics** | 是否启用指标；为 true 且未设 Metrics 时使用默认实现。详见 [指标](/docs/config/metrics) |
| **WithActorSystemMetrics** | 自定义指标收集器。详见 [指标](/docs/config/metrics) |
| **WithActorSystemEnableMetricsUpdatedNotify** | 指标更新通知策略：&lt;0 不推送，0 每次变更推送，&gt;0 按间隔推送。详见 [指标](/docs/config/metrics) |
| **WithActorSystemRemoting** | 启用远程通讯：bindAddr 必填，advertiseAddr 可选。详见 [远程通讯](/docs/config/remoting) |
| **WithActorSystemCodec** | 未注册业务类型的外部编解码器，可与消息注册同时使用。详见 [远程通讯](/docs/config/remoting) |
| **WithActorSystemMessageRegister** | 注册业务消息类型与字段编解码器，已注册类型优先于外部 Codec。详见 [远程通讯](/docs/config/remoting) |
| **WithActorSystemRemotingOptions** | 远程高级选项（如重试策略、读取超时、解码预算）。详见 [远程通讯](/docs/config/remoting) |
| **WithActorSystemRemotingOption** | 远程选项的链式增量配置（如 ReconnectLimit、ReconnectInitialDelay 等），可传多个 Option。详见 [远程通讯](/docs/config/remoting) |
| **WithActorSystemRemotingDecodeLimits** | 单个接收信封的解码预算，通过 WithActorSystemRemotingOption 传入；默认 64 层、累计 1048576 个集合元素和 64 MiB 分配预算。详见 [远程通讯](/docs/config/remoting) |
| **WithActorSystemClusterOptions** | 配置并启用集群，需设置集群名称并启用 Remoting。详见 [集群](/docs/cluster) |
| **WithActorSystemOptions** | 一次性应用整份 ActorSystemOptions |

## 使用方式

通过 **bootstrap.NewActorSystem** 直接传入 Option，或先 **NewActorSystemOptions** 再 **WithActorSystemOptions** 传入：

```go
system := bootstrap.NewActorSystem(
    vivid.WithActorSystemDefaultAskTimeout(5*time.Second),
    vivid.WithActorSystemStopTimeout(2*time.Minute),
    vivid.WithActorSystemRemoting("0.0.0.0:8080", "node1.example.com:8080"),
)
```

## Actor 创建

系统根 Actor 创建前调用 **`ActorSystem.ActorOf`** 会返回 **`ErrorActorSystemNotStarted`**。

**`system.ActorOf`** 可由多个 goroutine 调用，创建可与已有 Actor 的终止同时进行。创建子 Actor 则在所属 Actor 的消息处理流程内调用 **`ctx.ActorOf`**，详见[创建与生命周期](/docs/basics/lifecycle)。

## 系统停止

**`system.Stop(timeout...)`** 通过系统消息发起关闭，普通邮箱暂停不会阻断停止。框架执行 **OnKill** 和多阶段收尾，先停止业务 Actor，再依次停止集群、远程通信和指标组件。停止不保证排空普通消息；需要保存状态或完成业务请求时，应先取得业务完成确认。请在该系统的 Actor 消息线程之外调用。

业务 Actor 之间不保证停止顺序，父 Actor 会等待其子 Actor 结束；上述组件逐个停止，前一个组件结束后才停止下一个。

启动初始化期间调用 **Stop** 会等待当前 **Start** 初始化链结束，再清理已经创建的组件；此时 **Start** 返回 **ErrorActorSystemStopped**。启动期间的第二次 **Start** 返回 **ErrorActorSystemAlreadyStarted**。关闭开始后，新的 **ActorSystem.ActorOf** 返回 **ErrorActorSystemStopped**；停止开始前已进入创建流程的 Actor 会纳入关闭。

`timeout` 限制本次调用的等待时间，不传时使用 **WithActorSystemStopTimeout**，默认 1 分钟；显式传入 `<= 0` 表示一直等待。超时返回 **ErrorActorSystemStopFailed**，可用 `errors.Is(err, context.DeadlineExceeded)` 判断原因；后台继续关闭，可再次调用 **Stop** 等待。关闭完成后重复调用返回 **ErrorActorSystemAlreadyStopped**，系统不能重新启动。

停止无法强行中断阻塞的用户回调。等待超时不代表全部 Actor 或资源已经释放，也不会提前取消仍在收尾的系统上下文和调度器；回调需自行结束阻塞。

## 常见错误

系统级操作可能返回预定义错误，建议用 **errors.Is** 判定：**ErrorActorSystemAlreadyStarted**（重复 Start）、**ErrorActorSystemAlreadyStopped**、**ErrorActorSystemNotStarted**、**ErrorActorSystemStartFailed** / **ErrorActorSystemStopFailed**。详见 [错误](/docs/config/errors)，完整列表见 [pkg.go.dev - vivid](https://pkg.go.dev/github.com/kercylan98/vivid#pkg-variables)。
