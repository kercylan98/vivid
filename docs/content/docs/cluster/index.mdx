集群依赖 [远程通讯](/docs/config/remoting)，通过 **WithActorSystemClusterOptions** 启用。框架创建内部 `@gossip` Actor，利用 Ping/Pong 交换成员视图和版本向量，并在系统停止时执行多阶段退出。

## 启动与通信

每个节点使用 Remoting 的广告地址进行通信，每次启动生成独立的成员实例 ID。无种子时独立启动；配置种子后默认必须加入成功，失败不会自动自举。主动建立新组可显式启用 Bootstrap。`Start()` 启动运行时，`ClusterReady()` 提供初始加入结果。

集群内部消息的编解码由框架注册。跨节点业务消息仍使用常规 Tell、Ask 等 API，并需要配置业务消息的编解码。业务无需导入 `internal` 包。

## 当前能力范围

当前实现提供成员发现、成员视图同步、退出状态传播，以及 `system.ClusterSnapshot()` 本地只读查询、初始加入结果等待和成员变更事件。公开接口未提供 `ClusterContext`、`ctx.Cluster()`、`system.Cluster()`、Quorum、加入认证或集群单例能力；版本向量用于视图合并，不能据此推导多数派或脑裂防护保证。
