title: 连接认证
description: 使用 Remoting TLS/mTLS 配置节点连接身份与信任边界
---

集群复用 Remoting 连接。通过 `WithActorSystemRemotingTLSConfig` 为入站和出站统一配置 TLS；需要双方提供证书时启用 mTLS。完整配置示例见[远程通讯](/docs/config/remoting#tls-与双向认证)。

## 节点证书

每个节点同时作为服务端和客户端。mTLS 证书需支持两种认证用途，SAN 需包含其他节点访问它时使用的 DNS 名称或 IP。

`RootCAs` 验证出站服务端；`ClientCAs` 与 `ClientAuth` 控制入站客户端认证。集群所有节点需使用相容的传输配置和信任关系，TLS 失败不会降级为明文。证书握手成功仍需继续等待初始加入结果，见[启动与加入就绪](/docs/cluster/runtime/readiness)。

## 接入边界

通过 `WithActorSystemClusterName` 为每个节点设置逻辑集群名称。加入与周期 Gossip 只接收名称完全相同的成员视图；不同环境应使用不同名称。名称不匹配的加入响应不携带成员视图，调用方可通过 `ErrorClusterNameMismatch` 判断原因。

名称是公开标识，不是认证凭据，不能阻止主动伪造或隔离直接远程业务消息。部署网络中应限制可访问 Remoting 端口的来源。种子列表只是联络地址；当前没有集群级加入令牌或地址白名单。

mTLS 验证受信证书，不自动将对方声明的 Remoting 地址绑定到证书身份，也不授予业务操作权限。可通过同一信任域建立连接的节点，应纳入同一接入边界考虑；业务权限需在应用协议中校验。
