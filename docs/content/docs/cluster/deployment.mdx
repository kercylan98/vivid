集群通过 Remoting 交换成员视图。部署前需确定节点的可达地址、初始加入方式和连接认证；可运行示例见[快速开始](/docs/cluster/quick-start)。

## 地址与网络

- 每个运行中的节点使用独立的广告地址，格式为 `host:port`。监听所有网卡或使用端口映射时，分别配置绑定地址和广告地址。
- 种子填写目标节点的广告地址，不含 Actor 路径。`0.0.0.0`、`::` 不能作为其他节点的连接目标。
- 节点发现彼此后可直接连接。网络策略须允许成员间通信，不能只开放到种子的连接。
- 跨可信网络边界时配置 [TLS/mTLS](/docs/cluster/auth/join-auth)。种子列表用于发现，不是加入白名单。

## 启动与加入

先启动初始节点，再启动配置了种子的节点。无种子或显式配置 `WithActorSystemClusterBootstrap(true)` 时独立启动；其余节点默认必须收到有效加入响应。

<Mermaid diagram={`flowchart TD
  Start[启动系统] --> Listen[Start 成功：本地监听已创建]
  Listen --> Mode{无种子或显式 Bootstrap?}

  Mode -->|否| Join[尝试加入种子]
  Join -->|有效响应| Up[加入完成并进入 Up]
  Join -->|全部失败| Failed[保持 Joining，报告初始加入失败]

只配置自身种子不会自动自举。全部种子失败后不会自动重新尝试整轮加入，应检查地址、证书与启动顺序，停止后重新创建系统。等待方式与超时见[启动与加入就绪](/docs/cluster/runtime/readiness)。

## 持续观察

进入 Up 后，节点定期与抽样成员及配置的种子交换视图。使用 `ClusterSnapshot()` 查询本地成员，通过成员的 `Reachability` 读取本地往返观察，订阅 `ves.ClusterMembersChangedEvent` 和 `ves.ClusterReachabilityChangedEvent` 观察后续变化，见[本地成员查询](/docs/cluster/runtime/context)与[成员事件](/docs/cluster/events/events)。

可达性观察复用 Gossip 消息，详见[本地可达性](/docs/cluster/runtime/reachability)。

成员按每次启动的实例 ID 区分。同地址重启后会保留历史实例和退出记录，因此成员总数、Up 数量都不等于健康节点数。Gossip 传递完整成员视图，节点规模与历史记录增长会增加通信量；调大目标数或缩短周期也会增加网络和处理成本。

## 分区与恢复验证

至少验证启动时种子不可达、已有连接中断，以及恢复后新发出的双向业务请求。分别检查：

| 层次 | 验证内容 |
|------|----------|
| 连接 | 广告地址可达，双方传输模式与证书信任一致 |
| 成员 | 初始加入结果、本地成员视图及变更事件符合预期 |
| 业务 | 新请求得到有效应答，超时重试有去重措施，数据恢复符合业务约束 |

网络分区不会自动将成员标记为 Removed，成员视图恢复也不代表业务数据恢复。跨机房的能力边界与验证建议见[多数据中心](/docs/cluster/topology/multi-datacenter)。

## 正常停止

通过 `system.Stop()` 停止节点，集群随系统执行退出流程。`WithActorSystemClusterGracefulShutdownTimeout` 控制集群阶段的等待预算，系统停止预算也需覆盖业务收尾时间；检查 `Stop()` 的返回错误。

退出不保证所有远端已确认，也不保证待发送业务消息已交付。强制终止可能留下 Up 的旧实例记录，详见[节点生命周期](/docs/cluster/events/lifecycle)。
