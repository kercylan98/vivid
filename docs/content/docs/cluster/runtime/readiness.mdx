---
title: 启动与加入就绪
description: 区分运行时启动、加入成功、独立启动与加入失败
---

`Start()` 同步初始化运行时及集群组件，本地 Remoting 监听创建失败会直接返回错误；Actor 的启动回调与集群加入仍异步执行。需要等待初始加入结果时，调用 `system.ClusterReady(timeout...).Result()`；Actor 内可使用 `ctx.System().ClusterReady(...).PipeTo(...)` 接收结果。

## 默认启动规则

| 配置 | 行为 |
|------|------|
| 未配置种子 | 独立启动并进入 Up |
| 配置种子，Bootstrap 为 false（默认） | 依次尝试加入非本地种子，收到有效响应后进入 Up |
| Bootstrap 为 true | 独立启动并进入 Up，之后仍联络种子 |

配置了种子却全部加入失败时，返回 `ErrorClusterJoinFailed`，节点停留在 Joining，不自动成为孤岛，也不自动重启新一轮加入。传输请求错误会在单个种子的加入预算内有限重试；耗尽所有种子后，应检查集群名称、地址与启动顺序，再停止并重新创建系统。只有自身种子时必须显式启用 Bootstrap，避免把配置错误当作加入成功。

种子名称不匹配时拒绝加入，并继续尝试后续种子。全部失败时，错误保留每个种子的地址与最终原因；名称误配和超时可分别用 `errors.Is` 判断，不受种子顺序影响。名称误配信息还包含双方名称。后续种子加入成功则返回成功。Bootstrap 同样遵守名称匹配规则。

需要建立初始组，或明确允许分区两侧独立启动后重新发现时，使用 `WithActorSystemClusterBootstrap(true)`。这不会授予独占写入资格，也不提供业务数据合并。

## 等待结果

```go
func waitCluster(system vivid.ActorSystem) error {
    result, err := system.ClusterReady(10 * time.Second).Result()
    if err != nil {
        return err
    }
    if result.Bootstrapped {
        fmt.Printf("独立启动：%s\n", result.LocalID)
    } else {
        fmt.Printf("加入完成：%s，种子：%s\n", result.LocalID, result.SeedAddress)
    }
    return nil
}
```

结果包含 `LocalID`、`Bootstrapped` 和 `SeedAddress`；独立启动时 SeedAddress 为空。加入成功表示已收到种子对本实例的有效加入响应，不代表所有节点已同步、当前健康或多数派授权。结果是本次系统启动的初始结果，后续分区不会将成功结果改成失败；当前状态请查询[本地成员视图](/docs/cluster/runtime/context)。

未指定等待超时时，`ClusterReady()` 等待本次初始加入结果或系统停止；传入正数可限制当前调用的等待时间，传入 `<= 0` 表示不限等待时间。超时或 `Future.Close(err)` 只结束本次调用的等待，不取消节点加入，不影响其他等待者；等待失败后可再次读取同一次初始结果。系统停止会结束尚未完成的等待。

`WithActorSystemClusterJoinTimeout` 控制每个种子的加入总超时，包含有限重试和本地响应处理等待；处理时已过期的确认不会完成加入。种子会先去除自身和重复项，再按地址排序；传输请求失败会在该种子的总超时内有限重试，收到拒绝或无效响应则尝试下一个种子。多个种子、启动延迟及本地调度延迟可能使结果返回晚于单个种子的超时；调用方的等待时间由 `ClusterReady(timeout...)` 单独控制。

启动延迟和等待种子期间仍可查询快照或停止系统。快照可能显示 None、Joining，不能用查询成功代替加入完成。错误判定见[集群错误](/docs/cluster/errors)。
