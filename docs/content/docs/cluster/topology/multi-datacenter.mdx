当前节点可通过可达的 Remoting 广告地址跨机房通信，但集群不区分数据中心、地域或可用区，也没有按机房选择成员、路由或调整超时的配置。

## 地址与种子

每个节点使用其他节点能够访问的广告地址；种子填写广告地址，格式为 `host:port`。部署方式见[快速开始](/docs/cluster/quick-start)，连接配置见[远程通讯](/docs/config/remoting)。

为让独立启动的两组节点在链路恢复后发现彼此，应在至少一侧保留指向另一侧的种子地址。已经互相发现的成员也会参与周期目标选择，但不应仅依赖历史成员记录维持重启后的联络路径。

配置种子后，初始加入失败不会自动自举。若需要两侧独立启动，须在各自的初始节点上明确配置 `WithActorSystemClusterBootstrap(true)`；其他节点加入本组种子。启动结果见[启动与加入就绪](/docs/cluster/runtime/readiness)。

进入 Up 后，周期 Gossip 会继续联络配置的种子地址，并与已有成员共享每轮目标数。链路恢复且地址可达时，成员视图可继续交换；随机抽样、Gossip 周期与连接重试会影响恢复耗时。种子同地址重启后按新实例加入，旧实例记录继续保留，详见[节点生命周期](/docs/cluster/events/lifecycle)。

## 分区期间的行为

网络不可达不等于节点已离开集群。视图中的 Up 状态不能作为实时健康、可达性或写入资格的依据。通过成员的 `Reachability` 读取本地直接往返观察；超时及结果过期的含义见[本地可达性](/docs/cluster/runtime/reachability)。

成员视图恢复也不代表业务消息必达、业务数据合并或全局唯一 Actor 恢复。系统没有 Quorum、租约、写入隔离或跨节点虚拟 Actor 唯一激活保证；关键写入需由业务使用具备相应一致性能力的存储或协调服务约束。

从各自可见的 Up 数量计算多数派，不能约束分区另一侧的写入。需要独占操作时，授权必须能被存储或资源端校验；收到旧成员消息或网络恢复，均不表示旧授权已经失效。

## 部署前验证

结合链路延迟、调度负载与节点规模设置 Gossip 周期、探测预算和观察有效期，至少验证启动时隔离、已有连接中断及链路恢复后的双向通信。跨机房传输还需验证延迟、丢包和单向故障；单机上的多节点演练不能替代真实地域网络测试。
