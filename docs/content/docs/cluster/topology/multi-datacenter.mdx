节点可通过可达的 Remoting 广告地址跨机房通信，使用 `WithActorSystemClusterDataCenter` 声明所属机房，并通过成员快照与事件读取。声明后按机房轮换新观察与其余 Gossip 发送；当前不按机房路由业务或调整超时，也没有地域、可用区的独立配置。

## 声明与观察机房

```go
system := bootstrap.NewActorSystem(
    vivid.WithActorSystemRemoting("0.0.0.0:8081", "node2:8081"),
    vivid.WithActorSystemClusterOptions(
        vivid.WithActorSystemClusterName("example-prod"),
        vivid.WithActorSystemClusterDataCenter("cn-east-1"),
        vivid.WithActorSystemClusterSeeds("node1:8080"),
    ),
)
```

机房标识为空表示未声明，不从 IP 或集群名称推断。非空时须为 1–128 字节的有效 UTF-8，不含空白或控制字符，区分大小写，不自动裁剪。标识在本次启动内固定；需要调整时重新创建系统，同地址的新实例可以声明其他机房，历史实例保留原标识。

通过 `ClusterSnapshot()` 返回的 `ClusterMember.DataCenter` 读取；成员事件与可达性事件的快照也包含该字段。标识会随成员视图经其他节点转发，使用方式见[本地成员查询](/docs/cluster/runtime/context)和[成员事件](/docs/cluster/events/events)。这是节点自行声明的拓扑信息，不是认证结果、网络隔离条件或写入资格。

## 机房间的观察机会

本地声明机房并进入 Up 后，空闲观察额度优先交给最久未开始新观察的机房，再在该机房内轮换地址。本机房与远端机房遵循相同规则，小机房不会因节点数量少而只能等待大机房的全部地址先轮完；相应地，大机房遍历全部地址可能需要更多轮次。没有空闲候选的机房暂时跳过，等待中的请求继续受原探测预算约束。

未知种子、未声明机房的地址共用未知组。同地址存在多个可联络实例且声明不一致时，也按未知组处理；退出墓碑不参与机房分类。候选集合变化会更新分组，同地址的历史实例仍各自保留声明。

新观察优先使用每轮发送名额；剩余名额按最久未发送的机房、机房内地址轮换，已安排的新观察也计入本轮机房联络。观察并发满额时仍继续普通 Gossip，避免小机房在剩余发送名额中长期被忽略。发送历史只记录提交发送的尝试，不代表远端收到或确认。

本地未声明机房时，新观察按全体地址轮换，其余发送随机选择。轮换复用已有 Gossip，不增加独立探测消息，每条仍携带全量成员视图。新观察可能占满发送名额，因此不保证全部发送在机房间均分；这不是跨机房带宽限制，也不保证故障发现时限，预算说明见[本地可达性](/docs/cluster/runtime/reachability)。

跨机房应答较慢时，可独立调整 `WithActorSystemClusterMaxConcurrentProbes`，无需同时增大 `GossipPeersCount` 的每轮发送数量。更大的观察并发会保留更多等待记录；具体选择应结合链路延迟、探测预算和成员规模验证。

成员与版本未变时，Ping/Pong 复用只读发送视图以减少重复分配；成员变化后仍发送完整视图。该复用不减少消息数量或跨机房传输字节，部署时仍需评估成员规模带来的编码与带宽成本。

## 地址与种子

每个节点使用其他节点能够访问的广告地址；种子填写广告地址，格式为 `host:port`。部署方式见[快速开始](/docs/cluster/quick-start)，连接配置见[远程通讯](/docs/config/remoting)。

跨机房仍属于同一逻辑集群时，各节点使用完全相同的 `WithActorSystemClusterName`。不同名称的组不会合并成员视图，不能用不同名称表示需要相互发现的机房。

为让独立启动的两组节点在链路恢复后发现彼此，应在至少一侧保留指向另一侧的种子地址。已经互相发现的成员也会参与周期目标选择，但不应仅依赖历史成员记录维持重启后的联络路径。

配置种子后，初始加入失败不会自动自举。若需要两侧独立启动，须在各自的初始节点上明确配置 `WithActorSystemClusterBootstrap(true)`；其他节点加入本组种子。启动结果见[启动与加入就绪](/docs/cluster/runtime/readiness)。

进入 Up 后，周期 Gossip 会继续联络配置的种子地址，并与已有成员共享每轮目标数。链路恢复且地址可达时，成员视图可继续交换；地址轮换、Gossip 周期、观察预算与连接重试会影响恢复耗时。种子同地址重启后按新实例加入，旧实例记录继续保留，详见[节点生命周期](/docs/cluster/events/lifecycle)。

## 分区期间的行为

网络不可达不等于节点已离开集群。视图中的 Up 状态不能作为实时健康、可达性或写入资格的依据。通过成员的 `Reachability` 读取本地直接往返观察；超时及结果过期的含义见[本地可达性](/docs/cluster/runtime/reachability)。

成员视图恢复也不代表业务消息必达、业务数据合并或全局唯一 Actor 恢复。系统没有 Quorum、租约、写入隔离或跨节点虚拟 Actor 唯一激活保证；关键写入需由业务使用具备相应一致性能力的存储或协调服务约束。

从各自可见的 Up 数量计算多数派，不能约束分区另一侧的写入。需要独占操作时，授权必须能被存储或资源端校验；收到旧成员消息或网络恢复，均不表示旧授权已经失效。

## 部署前验证

结合链路延迟、调度负载与节点规模设置 Gossip 周期、探测预算和观察有效期，至少验证启动时隔离、已有连接中断及链路恢复后的双向通信。跨机房传输还需验证延迟、丢包和单向故障；单机上的多节点演练不能替代真实地域网络测试。
