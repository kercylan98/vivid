当前节点可通过可达的 Remoting 广告地址跨机房通信，但集群不区分数据中心、地域或可用区，也没有按机房选择成员、路由或调整超时的配置。

## 地址与种子

每个节点使用其他节点能够访问的广告地址；种子填写广告地址，格式为 `host:port`。部署方式见[快速开始](/docs/cluster/quick-start)，连接配置见[远程通讯](/docs/config/remoting)。

若希望隔离的两组节点在链路恢复后重新发现对方，至少需要一侧保留指向另一侧的种子地址。种子之间无需全部互联，但不能让两组节点的成员与种子都完全独立。

节点启动时联系不上种子，会自举为独立集群。进入 Up 后，周期 Gossip 会继续尝试未知或仍处于 Joining 的种子，并与已有成员共享每轮目标数。链路恢复且地址可达时，成员视图可继续交换；随机抽样、Gossip 周期与连接重试会影响恢复耗时。已明确标记 Removed 的种子不属于自动重新发现对象。

## 分区期间的行为

网络不可达不等于节点已离开集群。当前实现没有成员故障检测，视图中的 Up 状态不能作为实时健康、可达性或写入资格的依据。

成员视图恢复也不代表业务消息必达、业务数据合并或全局唯一 Actor 恢复。系统没有 Quorum、租约、写入隔离或跨节点虚拟 Actor 唯一激活保证；关键写入需由业务使用具备相应一致性能力的存储或协调服务约束。

## 部署前验证

按业务可接受的时间设置 Gossip 周期和远程连接超时，至少验证启动时隔离、已有连接中断及链路恢复后的双向通信。跨机房传输还需验证延迟、丢包和单向故障；单机上的多节点演练不能替代真实地域网络测试。
