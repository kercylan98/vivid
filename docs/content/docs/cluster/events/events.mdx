description: 订阅本地成员变更并处理快照与事件顺序
---

通过 `system.ClusterSnapshot()` 查询本地成员视图，通过 `ves.ClusterMembersChangedEvent` 订阅后续变更。这些结果反映本节点已知的信息，不表示实时健康、多数派确认或接管资格。

查询方法及成员字段见[本地成员查询](/docs/cluster/runtime/context)。

## 订阅变更

在 Actor 中订阅值类型事件，响应使用现有的 `PipeTo` 投递回本 Actor：

```go
type Observer struct{}

func (a *Observer) OnReceive(ctx vivid.ActorContext) {
    switch message := ctx.Message().(type) {
    case *vivid.OnLaunch:
        ctx.EventStream().Subscribe(ctx, ves.ClusterMembersChangedEvent{})
        ctx.System().ClusterSnapshot(time.Second).PipeTo(ctx.Ref().ToActorRefs())
    case *vivid.PipeResult:
        if message.Error != nil {
            ctx.Logger().Error("cluster snapshot failed", log.Any("error", message.Error))
            return
        }
        snapshot := message.Message.(vivid.ClusterSnapshot)
        ctx.Logger().Info("initial cluster snapshot", log.Uint64("revision", snapshot.Revision()), log.Int("members", snapshot.Len()))
    case ves.ClusterMembersChangedEvent:
        ctx.Logger().Info("cluster members changed", log.Uint64("revision", message.Snapshot.Revision()), log.Int("members", message.Snapshot.Len()))
    }
}
```

事件的 `Snapshot` 是变更后的完整只读视图。本节点状态迁移、接收到更高版本的成员记录时发布；一批 Gossip 合并发布一次，重复或旧版本消息不会重复通知。事件通过本地 EventStream 投递到订阅者邮箱，不在 Gossip 处理中执行用户回调。

先订阅，再查询初始快照。两者不是原子操作，事件可能先于查询结果到达；维护本地状态时，应在相同 LocalID 下保留 Revision 最大的视图，忽略较旧或重复结果。LocalID 变化表示观察实例改变，应重新查询建立基线，不能比较不同 LocalID 的序号。

订阅不回放历史事件，也不保证系统关闭前所有事件都已被消费。快照与事件用于本地观察，框架未为其注册跨节点传输编解码。

同地址重启会出现不同实例 ID；崩溃旧实例仍可能显示 Up。因此 Len 和 Up 记录数都不能作为健康节点数，详见[节点生命周期](/docs/cluster/events/lifecycle)。
