## 概述

每个 **ActorContext** 拥有独立的 **Scheduler** 实例，通过 `ctx.Scheduler()` 获取。调度器用于在指定时间或周期向**目标 ActorRef**（通常为当前 Actor 或子 Actor）**投递消息**。

- **生命周期**：任务与创建它的 Actor 绑定，终止或重启收尾后自动清理，旧 Scheduler 永久拒绝新任务；重启初始化时需重新调用 `ctx.Scheduler()` 并注册任务。`OnKill`、自身 `OnKilled` 收尾期间仍可注册，随后一并清理；`Stop` 等待超时不提前关闭仍在收尾的调度器。
- **作用域**：reference 在所属 Scheduler 内唯一；不同 Actor、同路径重建的 Actor 可使用相同 reference，清理任务互不影响。`system.Scheduler()` 属于根 Actor。
- **投递边界**：取消或清理任务不会撤回已取出、正在投递或已进入邮箱的消息。
- **并发操作**：同一 Scheduler 支持并发注册、查询、取消与清理；相同 reference 的重复注册失败，不替换原任务。注册失败不会新增登记，`Exists` 只反映查询当时的状态。

调度在本进程运行；向远程 Actor 投递沿用普通消息传输，不提供任务持久化或故障后补执行。Actor 已收尾时注册返回 `ErrorActorDeaded`，系统停止完成后返回 `ErrorActorSystemStopped`；初始化失败也会关闭并清理本次调度器。

远程调度直接传输业务消息，须按普通远程消息配置编解码器或注册消息类型。

## 一次性延时（Once）

在**延时一段时间后**向目标 Actor **投递一次**消息。

**方法**：`Once(receiver ActorRef, delay time.Duration, message Message, options ...ScheduleOption) (ScheduledTask, error)`

| 参数 | 说明 |
|------|------|
| **receiver** | 接收消息的 ActorRef，常用 `ctx.Ref()` 发给自身 |
| **delay** | 从当前时刻起算的延时 |
| **message** | 待投递的消息 |
| **options** | 可选，如 **WithSchedulerReference(id)** 便于后续取消或查询 |

```go
task, err := ctx.Scheduler().Once(ctx.Ref(), 5*time.Second, &MyMessage{Data: "delayed"})
```

- 注册成功返回任务句柄和 `nil`；失败返回 `nil` 和错误。非正延时的任务可能在注册方法返回前已取出投递。
- **delay 非正**时尽快异步投递一次；到期可能因运行时调度而延迟，不因超过延时自动丢弃。
- 任务取出投递时自动移除登记，可以重新使用相同 reference；此时消息可能仍在投递途中。

## 固定间隔循环（Loop）

按**固定间隔**重复向目标 Actor 投递消息，直到任务被取消或 Actor 终止。

**方法**：`Loop(receiver ActorRef, interval time.Duration, message Message, options ...ScheduleOption) (ScheduledTask, error)`

| 参数 | 说明 |
|------|------|
| **receiver** | 接收消息的 ActorRef |
| **interval** | 两次投递之间的时间间隔，必须大于零 |
| **message** | 每次触发时投递的消息 |
| **options** | 可选，如 **WithSchedulerReference(reference)** 便于后续取消 |

```go
task, err := ctx.Scheduler().Loop(ctx.Ref(), 10*time.Second, &TickMessage{})
```

周期为零或负值时，返回 `nil` 和 `ErrorIllegalArgument`，不创建任务。立即异步投递一次请使用 `Once`。

## Cron 表达式（Cron）

使用 **Cron 表达式**定义日历式调度，在匹配的时间点向目标 Actor 投递消息。

**方法**：`Cron(receiver ActorRef, cron string, message Message, options ...ScheduleOption) (ScheduledTask, error)`

| 参数 | 说明 |
|------|------|
| **receiver** | 接收消息的 ActorRef |
| **cron** | 六段 Cron 表达式：秒 分 时 日 月 周，可追加第七段年份，如 `"0 0 0 * * ?"` 表示每天 0 点 |
| **message** | 在匹配时间点投递的消息 |
| **options** | 可选，**WithScheduleLocation(loc)** 控制时区（默认 **time.Local**），**WithSchedulerReference** 便于取消 |

```go
// 每天 0 点
task, err := ctx.Scheduler().Cron(ctx.Ref(), "0 0 0 * * ?", &DailyJob{})
```

- 若 Cron 表达式非法，返回 **ErrorCronParse**。

## 任务管理

`Once`、`Loop`、`Cron` 注册成功均返回 **ScheduledTask**。保存句柄即可查询和取消，无需自行生成名称：

```go
task, err := ctx.Scheduler().Once(ctx.Ref(), time.Minute, msg)
if err != nil {
    return err
}
reference := task.Reference() // 未指定时由框架生成
exists := task.Exists()      // 本次注册是否仍有登记
err = task.Cancel()         // 只取消本次注册
```

句柄绑定一次注册。同名任务重新注册或 Actor 重启后，旧句柄不会查询或取消新任务；旧登记释放后 `Exists()` 返回 `false`，`Cancel()` 返回 `ErrorNotFound`。这些结果不表示消息已处理。

如需按名称管理任务，可在注册时指定 `WithSchedulerReference(reference)`。`Scheduler.Exists(reference)` 和 `Scheduler.Cancel(reference)` 始终作用于当前同名登记。

### 检查任务是否存在（Exists）

查询当前 Scheduler 是否保留指定 reference 的登记。

**方法**：`Exists(reference string) bool`

- 返回 **true** 表示仍有登记，**false** 表示没有登记。一次任务在取出投递时移除登记；`Cron` 等底层任务到期后仍可能保留登记。不能据此判断消息是否已处理。

### 取消任务（Cancel）

按 reference 取消当前同名任务；只取消某次注册时使用 `task.Cancel()`。

**方法**：`Cancel(reference string) error`

- 取消成功返回 **nil**。
- 若 reference 不存在，返回 **ErrorNotFound**。
- 一次任务已取出投递时返回 **ErrorNotFound**；后续投递仍可能完成。

```go
refID := "my-timer-1"
_, err := ctx.Scheduler().Once(ctx.Ref(), time.Minute, msg, vivid.WithSchedulerReference(refID))
if err != nil {
    return err
}
err = ctx.Scheduler().Cancel(refID)
```

### 清空全部任务（Clear）

取消当前 Scheduler 上**全部**已注册任务。

**方法**：`Clear()`

- 无参数、无返回值，清除当前任务；不禁止后续注册，并发注册的任务可能在清理后加入。

## 调度选项（ScheduleOptions）

通过 **vivid.NewScheduleOptions** 或 **WithScheduleOptions**、**WithScheduleLocation**、**WithSchedulerReference** 配置：

| 选项 | 说明 |
|------|------|
| **Location** | Cron 使用的时区，默认 **time.Local** |
| **Reference** | 任务唯一标识，用于 **Exists** / **Cancel**；不传则自动生成 |
